# ai-takeover: план событий и финальной главы

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking. Работать последовательно в основной сессии согласно предпочтению Виктора.

**Статус:** реализовано 2026-11-05 в `feature/narrative-finale`; без коммита и деплоя. 65 тестов, typecheck/build, 1100 обычных и 1000 синтетических прогонов, браузерная и HTTP-приёмка. Два P2 замечания одного независимого ревью исправлены.

**Goal:** Сделать события понятными и выразительными, добавить короткую развязку с вычисляемым риском и восемь самостоятельных эпилогов.

**Architecture:** Детерминированные факты и финальная глава живут в src/core; клиент строит из них алерты, хронику, решения и эпилоги. Параметры и контент в data. Клиент, боты и сервер используют общие правила и расчёт вероятностей.

**Tech Stack:** Node >=24, TypeScript со стираемым синтаксисом, Phaser 4, Vite, HTML/CSS, npm; существующий node --test.

**Spec:** ../specs/2026-11-05-narrative-design.md

## Global Constraints

- Без новых зависимостей, коммитов и push.
- Не менять существующую формулу аудита в первой версии.
- Новая RULES_VERSION `finale-1`, таблица `scores_finale_1`. Старую таблицу не удалять.
- Настройки баланса и контент — в data; игровой RNG — только существующий поток ядра.
- Имена ИИ считать пользовательским текстом; никаких реальных имён, логотипов и портретного сходства в контенте.
- Обычная симуляция стоит во время последних решений; отсутствующие действия не должны вешать replay.
- Проверки: npm run typecheck, npm run build; lint-скрипта сейчас нет. Тесты логики необходимы для RNG, replay и серверной валидации.
- Итоговое ревью нетривиального diff можно предложить один раз; реализацию не делегировать.

## Review Focus

1. Несколько критических событий за такт: все доступны в очереди и хронике (этап 2).
2. Неполный или поддельный журнал финальных решений: ограниченное завершение с отказом сервера (этап 5).
3. Обычная карточка и порог победы в одном такте: одна активная модалка, один вход в главу (этап 4).
4. Нулевая мощность/ресурсы, крайние вероятности и неправильные ID: конечные числа, отказ без мутаций (этапы 3–4).
5. Перезапуск/пропуск эпилога, узкий экран и reduced motion: нет старых обработчиков, звук/пауза не ломаются (этап 6).

## Последовательность и границы

1–2 дают самостоятельное обновление событий. 3–5 вместе дают законченную финальную игровую главу; промежуточный незавершённый режим не выпускать. 6 добавляет постановку всех концовок. 7 — общая приёмка. Номера этапов этого документа не являются задачами T-NNN; существующий vault не изменён.

## Решения при реализации

- Иллюстрации восьми концовок хранятся одним атласом `public/endings/atlas.png`; сцены используют отдельные области. Замена одной иллюстрации требует обновить атлас.
- Конкретные веса/цены и визуальный стиль выбраны исполнителем в рамках разрешения выполнить весь план; проверены прогонами и браузером. Редкие концовки и привлекательность рискованного пути требуют ручной оценки.
- Работа выполнена в новой feature-ветке чистого checkout, без отдельной копии worktree и установки зависимостей.
- Учёт хода главы включает немедленную перепроверку сохранённого кандидата после обычной карточки; replay считает пики и после действий на одном такте.
- Результаты карточек дополнены сроками следующей волны/конца отключений и качественным указанием изменения курса ИИ.

Скриншоты приёмки сохранены в Downloads; подробные результаты баланса — в sim-model.
